# Flow Video Rendering

This module renders contact flow track overlays on DROID videos, showing the 3D contact surface evolution as colored point clouds and trajectory trails overlaid on camera feeds.

## Overview

The flow video rendering system visualizes robotic manipulation contact dynamics by:
1. Computing 3D contact points on gripper finger surfaces using mesh sampling
2. Normalizing trajectory flow at 1mm distance increments (distance-based vs time-based)
3. Projecting 3D contact points to 2D camera coordinates
4. Overlaying colored track points and trails on video frames

## Key Features

- **Normalized Flow**: Resamples trajectory at consistent 1mm steps for uniform analysis
- **Multi-Camera Support**: Renders for external cameras and wrist-mounted cameras
- **Contact Surface Tracking**: 480 contact points per finger (960 total)
- **Trail Visualization**: Shows contact point history with fading trails
- **Batch Processing**: Processes multiple episodes/shards automatically

## Scripts

### 1. `render_flow_videos.py`
Renders flow overlays on DROID episode videos using tracks.npz files.

**Usage:**
```bash
# Single episode with all cameras
python render_flow_videos.py --max_episodes 1

# Multiple episodes from specific labs
python render_flow_videos.py --max_episodes 5 --labs AUTOLab IRIS
```

**Input:** 
- `tracks.npz` files (generated by `generate_tracks_and_metadata.py`)
- Original MP4 videos from DROID dataset
- Camera extrinsics from `trajectory.h5`

**Output:** `*_flow.mp4` videos with overlay

### 2. `render_flow_from_shards.py`
Renders flow overlays on training shard videos (tar archives).

**Usage:**
```bash
# Process first 2 shards, 3 episodes each
python render_flow_from_shards.py --max_shards 2 --max_episodes 3

# Process specific shard directory
python render_flow_from_shards.py --shards_dir /path/to/shards --max_shards 5
```

**Input:**
- Training shard tar files (`shard_*.tar`)
- Contains: `*.npz` (metadata) + `*.mp4` (videos)

**Output:** `s*_flow.mp4` videos with overlay

### 3. `process_episodes_flow.py`
Batch processing pipeline that generates tracks and renders videos.

**Usage:**
```bash
# Process 10 episodes from AUTOLab and IRIS
python process_episodes_flow.py --max_episodes 10 --labs AUTOLab IRIS

# Skip existing tracks, only render videos
python process_episodes_flow.py --skip_existing --max_episodes 5
```

**Pipeline:**
1. Find DROID episodes with trajectory.h5
2. Generate tracks.npz if missing/outdated
3. Render flow overlay videos
4. Handle calibration errors gracefully

## Data Flow

```
DROID Episodes → tracks.npz → Flow Videos
     ↓              ↓             ↓
  MP4 videos   Contact points   Overlay
  trajectory.h5   (3D→2D)      rendering
```

## Track Data Format

Generated `tracks.npz` contains:
- `tracks_3d`: [T, 960, 3] - Contact points per frame (time-based)
- `normalized_tracks_3d`: [M, 960, 3] - Contact points per 1mm step (distance-based)
- `contact_centroids`: [T, 3] - Centroid per frame
- `normalized_centroids`: [M, 3] - Centroid per normalized step
- `frame_to_normalized_idx`: [T] - Mapping from frame to normalized step

## Visualization Elements

| Element | Color | Description |
|---------|--------|-------------|
| **Left finger tracks** | Blue | 480 contact points on left gripper finger |
| **Right finger tracks** | Green | 480 contact points on right gripper finger |
| **Track trails** | Faded | Connect consecutive positions (10 frame history) |
| **Contact centroid** | Yellow/Cyan | Center of mass of all contact points |
| **Frame info** | White text | Frame number and normalized step index |

## Fixed Issues

### Mesh Unit Conversion
The original STL mesh (`inner_finger_fine.STL`) was in millimeters, causing track coordinates to be 1000x too large. Fixed by adding automatic unit detection and conversion in `ContactSurfaceTracker.__init__()`:

```python
# Convert from mm to meters if mesh is in mm
if np.abs(finger_mesh.vertices).max() > 1.0:
    finger_mesh.vertices = finger_mesh.vertices / 1000.0
```
